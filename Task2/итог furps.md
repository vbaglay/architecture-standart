| Код  | Требование                                                                                     | Комментарий                                                                 |
|------|------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| **F** | **Функциональные требования**                                                                 |                                                                              |
| F1   | Подача заявки на депозит через сайт (ФИО, телефон, шифрование данных)                         | Обязательная идентификация клиента через офис.                             |
| F2   | Подача заявки через интернет-банк (выбор счёта, суммы, SMS-подтверждение)                     | Персонализированные ставки для клиентов.                                   |
| F3   | Централизованное хранение ставок (в АБС вместо XLS)                                           | Доступ для депозитного и кредитного бэк-офиса.                             |
| F4   | Передача заявок в кол-центр                                                                   | Автоматическая интеграция с системой кол-центра.                           |
| F5   | Согласование ставок вручную (MVP)                                                             | Обработка заявок сотрудниками бэк-офиса до автоматизации.                  |
| F6   | Отправка SMS-уведомлений                                                                      | Информирование клиентов о подтверждении заявки и открытии депозита.        |
| F7   | Возможность редактирования ставок                                                              | Интерфейс редактирования ставок для бэк-офисов.                            |
| F8   | Возможность предложить индивидуальные условия по ставке                                        | Менеджер кол-центра может скорректировать условия после звонка.            |
| F9   | Учёт обязательной идентификации клиента в бизнес-логике                                       | Например, статус заявки до очной верификации.                              |
| **U** | **Удобство использования**                                                                    |                                                                              |
| U1   | Единый дизайн интерфейсов (фирменный стиль: цвета, шрифты, UI-компоненты)                    | Снижение затрат на поддержку.                                              |
| U2   | Минималистичные формы (ФИО + телефон на сайте)                                                | Упрощение подачи заявки для новых клиентов.                                |
| U3   | Быстрый отклик интерфейса (<500 мс)                                                          | Оптимизация загрузки справочных данных (кэширование, асинхронные запросы). |
| **R** | **Надёжность**                                                                                |                                                                              |
| R1   | Доступность 24/7 (uptime 99.9%)                                                               | Резервный ЦОД, автоматическое переключение при сбоях.                      |
| R2   | Защита от перегрузки АБС                                                                      | Запрет прямых запросов к АБС — использование промежуточного слоя.          |
| R3   | Устойчивость к потере данных                                                                  | Отказ от XLS-файлов в пользу системного хранилища.                         |
| **P** | **Производительность**                                                                        |                                                                              |
| P1   | Обработка запросов в миллисекундах                                                            | Устранение задержек при загрузке справочников.                             |
| P2   | Горизонтальное масштабирование интернет-банка                                                 | Распределение нагрузки между серверами и ЦОД.                              |
| P3   | Минимальная задержка между подтверждением и отправкой SMS                                     | Критично для UX.                                                           |
| P4   | Поддержка высокой нагрузки                                                                     | Особенно при росте количества онлайн-заявок.                               |
| **S** | **Поддерживаемость**                                                                          |                                                                              |
| S1   | Использование текущего стека (MS SQL, Oracle, Java, C#)                                       | Минимизация зависимости от внешних подрядчиков.                            |
| S2   | Подготовка к микросервисной архитектуре                                                       | Документация и модульность для будущего расширения.                        |
| S3   | Совместимость с существующей инфраструктурой                                                  | Запрет на Kafka из-за несовместимости с текущей версией интернет-банка.    |
| S4   | Возможность доработки логики обработки заявок                                                 | Добавление состояний: «перезвонить позже», «ожидает уточнения».            |
| S5   | Поддержка корпоративной дизайн-системы                                                        | Единообразие интерфейсов всех цифровых каналов.                            |
| S6   | Документация для масштабирования системы                                                      | Важна для командной передачи и будущих проектов.                           |
| S7   | Проектирование масштабируемой архитектуры                                                     | Учёт баланса нагрузки между слоями и узлами.                               |
| **+R** | **Ограничения**                                                                              |                                                                              |
| +R1  | Обязательная офлайн-идентификация клиента                                                     | Регуляторное требование для заявок с сайта.                                |
| +R2  | Запрет прямого доступа к АБС                                                                  | Использование промежуточных сервисов или очередей.                         |
| +R3  | Вертикальное масштабирование АБС                                                              | БД Oracle не поддерживает горизонтальное масштабирование.                 |
| +R4  | Шифрование данных (TLS/HTTPS)                                                                 | Защита трафика при передаче данных.                                        |
| +R5  | Ограниченная производительность АБС                                                           | Новые процессы не должны создавать дополнительную нагрузку.                |
| +R6  | Ограниченная совместимость с новыми технологиями                                              | Пример: Kafka — не работает в текущем ИБ.                                  |
| +R7  | Технологии должны соответствовать компетенциям команды                                        | Использовать только те, с которыми есть опыт в банке.                      |
| +R8  | Запрет на XLS как систему учёта ставок                                                        | Нет надёжности, нет истории изменений, нет совместной работы.             |
